# tests/

| Path | What it is |
|---|---|
| `console/number_check.lua` | LuaJIT interpreter number check (from Love360). Run on PC with `luajit -joff tests/console/number_check.lua`; on the console the log has to end with `== numbers: 0 of 36 wrong ==`. |
| `console/rng_check.lua` | Known answers of `engine/rng.lua` (checked against a C version of the algorithms): seeds, named streams, a long run, `int`, `float`, `shuffle`, `weighted`, seed codes. On PC, from the repository root, `luajit tests/console/rng_check.lua` and `luajit -joff tests/console/rng_check.lua` must both end with `== rng: 0 of 29 wrong ==`. On the console: copy it next to the `main.lua` of a game that has `engine/`, add `require("rng_check")` as the first line of that `main.lua`, and the log has to end with the same line. |
| `console/procgen_check.lua` | Known layout hashes of `engine/modules/procgen` for a fixed set of templates and a few seeds. On PC, `luajit tests/console/procgen_check.lua` and `luajit -joff tests/console/procgen_check.lua` must both end with `== procgen: 0 of 6 wrong ==`. On the console, use it the same way as `rng_check.lua` (`require("procgen_check")`). |
| `console/items_check.lua` | Known draws of `engine/modules/items` with the loot stream of three seeds. On PC both `luajit` and `luajit -joff` must end with `== items: 0 of 3 wrong ==`; on the console use it like `rng_check.lua` (`require("items_check")`). |
| `pc/boot_pc.lua` | Runs the console boot (`runtime/lua/boot.lua`) on PC against a game, with a fake `l360` table and the graphics stub. `luajit -joff tests/pc/boot_pc.lua` must end with `OK:`. Needs `python3` (it runs the shader build with `--hlsl-only` for the fixture's metadata). |
| `pc/check_libs_test.lua` | `tools/check_libs.lua` passes on the repository, and reports every kind of problem in a copy with a broken library. `luajit tests/pc/check_libs_test.lua` must end with `OK:`. |
| `pc/compat_check_test.lua` | Checks `tools/compat_check.lua` against a fake `love` table (wrapping, pass-through, once-only lines, argument checks, callbacks, `report()`), and that `docs/API_SUBSET.md` and `tools/api_subset_data.lua` are up to date. `luajit -joff tests/pc/compat_check_test.lua` must end with `OK:`. |
| `pc/particles_test.c` | Checks `runtime/l360_particles.c` (the ParticleSystem simulation, which needs no xsdk) built for PC: the pool's cap, lifetimes, emission rate, movement, sizes and colours, emission areas, the three insert modes. `gcc -std=gnu17 -Wall -Wextra -Werror -Iruntime tests/pc/particles_test.c runtime/l360_particles.c -lm -o /tmp/particles_test && /tmp/particles_test` must end with `OK:`. |
| `engine/run.lua` | The engine layer's tests (`engine/`, `lib/anim8`, `lib/bump`) on plain LuaJIT with a small fake `love` (`engine/fake_love.lua`): state stack, fixed timestep, input edges and deadzones, camera, pixel scaling, layer order, anim8, entities, modifiers, seeded random numbers (`engine/rng.lua`: known answers, uniform ranges, independent streams, save state), saves (`engine/save.lua` with a fake `love.filesystem`: round trips, corrupt files, migrations, unlocks, a parser that rejects code), the platformer module (`engine/modules/platformer` on `lib/bump`: tiles merged into rectangles, solid and one-way collisions, coyote time, jump buffer, jump cut, drop-through, parameters changed by modifiers, the reach numbers), the frame loop, `examples/engine_demo`, and a static check of what `engine/` and anim8 call against the console's subset. `luajit -joff tests/engine/run.lua` must end with `OK:`, and so must `luajit tests/engine/run.lua` (JIT on for the random number tests only). `luajit -joff tests/pc/boot_pc.lua examples/engine_demo` runs the demo on the console's boot. |
| `fixtures/minimal_game/` | The smallest game: `game.lua`, `conf.lua`, `main.lua` and one shader (`shaders/tint.glsl`), plus a SpriteBatch tile map (`tiles.png`), text, lines and circles, and a ParticleSystem drawn with additive blending. Also runs on LÖVE 11.x. |
| `shaders/` | Shader build tests: the GLSL to HLSL translator, its xost rules and the metadata (with a small HLSL interpreter), and the notices file of `tools/shaders/xost_windows`. `python3 -m unittest discover -s tests/shaders` must end with `OK`; needs no Windows or xost. |

Love360's other PC tests (fake xsdk GPU, audio and file system for the C code) are not ported yet.
