# tests/

| Path | What it is |
|---|---|
| `console/number_check.lua` | LuaJIT interpreter number check (from Love360). Run on PC with `luajit -joff tests/console/number_check.lua`; on the console the log has to end with `== numbers: 0 of 36 wrong ==`. |
| `console/rng_check.lua` | Known answers of `engine/rng.lua` (checked against a C version of the algorithms): seeds, named streams, a long run, `int`, `float`, `shuffle`, `weighted`, seed codes. On PC, from the repository root, `luajit tests/console/rng_check.lua` and `luajit -joff tests/console/rng_check.lua` must both end with `== rng: 0 of 29 wrong ==`. On the console: copy it next to the `main.lua` of a game that has `engine/`, add `require("rng_check")` as the first line of that `main.lua`, and the log has to end with the same line. |
| `console/procgen_check.lua` | Known layout hashes of `engine/modules/procgen` for a fixed set of templates and a few seeds. On PC, `luajit tests/console/procgen_check.lua` and `luajit -joff tests/console/procgen_check.lua` must both end with `== procgen: 0 of 6 wrong ==`. On the console, use it the same way as `rng_check.lua` (`require("procgen_check")`). |
| `console/items_check.lua` | Known draws of `engine/modules/items` with the loot stream of three seeds. On PC both `luajit` and `luajit -joff` must end with `== items: 0 of 3 wrong ==`; on the console use it like `rng_check.lua` (`require("items_check")`). |
| `console/level_hash_check.lua` | The PC vs 360 level hash test: reads a hash list written by `tools/seed_validator.lua --out` and generates the same seeds again with the game's spec module, logging each mismatch. On PC: `luajit -joff tests/console/level_hash_check.lua <game folder> [list]`; on the console it must end with `== level hashes: 0 of N wrong ==`. Procedure: [docs/NEW_GAME.md](../docs/NEW_GAME.md). |
| `pc/template_test.lua` | `template/` boots on the console's boot and its example state runs on the fake love (movement by actions at 60 and 30 FPS). `luajit -joff tests/pc/template_test.lua` must end with `OK:`. |
| `pc/slime_test.lua` | `examples/slime` boots on the console's boot, and on the fake love the slime falls and rests on the floor, moves by key and by stick (also at 30 FPS), jumps, squashes, jumps higher after a squash, and is drawn as one pixel grid. `luajit -joff tests/pc/slime_test.lua` must end with `OK:`. |
| `pc/rooms_example_test.lua` | `examples/rooms`: its templates make a map for 50 seeds and fit their cells, it boots on the console's boot, and on the fake love the slime walks out of the start room through a door behind a fade, arrives inside the next room, a locked door holds until the key and then leads on, the minimap marks the explored rooms, a hall's enemies are there, landing on one stomps it and bounces the slime, a bite hurts the slime, each of its three attacks (melee, ranged, explosive) hurts an enemy and the switch button cycles them, dying sends it back to the start room healed, the treasure room holds one mutation that changes the run's stats or look without healing, the boss gives a mutation and opens stairs, a room remembers its dead enemies and their health, the start room's heart and virus pickups work, a crate breaks and stays broken, the test machine spends virus and heals once, an up/down door opens the border, a miniboss seals its doors, the room is drawn, Escape pauses (the play state stops updating) and Resume pops it, losing the pad in use auto-pauses with a menu that fits the screen and draws its text with rectangles, and Restart run asks first and then starts at floor 1. It also generates all ten floors of 20 seeds and checks that each has its special rooms and that the run grows, and walks the biome path of 200 runs (cellar first, core last, spans, the forge's floors, the ruins' kills). `luajit -joff tests/pc/rooms_example_test.lua` must end with `OK:`. |
| `pc/rooms_stats_test.lua` | `examples/rooms` stats and shield on `engine.modifiers`: schema and caps, unique/stackable mutations, tags, the combat source mapping, damage/health/jump modifiers, shield absorption and overflow, and the `5 + 2.5 * capacity` recharge. `luajit -joff tests/pc/rooms_stats_test.lua` must end with `OK:`. |
| `pc/rooms_content_test.lua` | `examples/rooms` mutation/consumable pools: entry schema and max, source/mob/floor filters, synergy/anti weights, luck multipliers, deterministic draws, unique/stackable limits, and drop chances. `luajit -joff tests/pc/rooms_content_test.lua` must end with `OK:`. |
| `pc/rooms_economy_test.lua` | `examples/rooms` wallet data helpers: pickups, breakable crates, and a machine with `accepts_money`, price, uses and per-machine state. `luajit -joff tests/pc/rooms_economy_test.lua` must end with `OK:`. |
| `pc/rooms_look_test.lua` | `examples/rooms` cosmetics: the base look, colours/eyes/shape/limbs, rebuild order, body fragments and the in-place outline scale. `luajit -joff tests/pc/rooms_look_test.lua` must end with `OK:`. |
| `pc/perf_platformer_test.lua` | `examples/perf_platformer` (objective 18): its files and config, a static check of what it calls against the console's subset, the console's boot as shipped and with the automatic benchmark on (every pair of counts measured, the results file written to the save folder and read back), and a run on the fake love with a SpriteBatch, a ParticleSystem, `getStats`, a clock and a save folder added: the same level for the same seed, the enemy and particle counts cycled by key and by controller button, the overlay's numbers, the player's attack, and the benchmark's results table. `luajit -joff tests/pc/perf_platformer_test.lua` must end with `OK:`. |
| `tools/` | Python tests of `tools/package.py` (with its `.ogg` conversion and `tools/audio_convert.py`: the chunk splitter, the music patterns, the cache; the real ffmpeg conversions are skipped without ffmpeg), `tools/ldtk_convert.py` (the mapping of `fixtures/ldtk/`, inferred exit sides, errors that name the level, the same bytes every time), `tools/install_ftp.py` and `tools/deploy.py` (the FTP ones against `fake_ftp.py`, an in-memory stand-in for `ftplib.FTP` that answers like Aurora's server): the packaged folder and its exclusions, validation, dry runs, the zip, changed-files-only uploads, saves never touched, the deploy steps and their order, its local config, and the XBDM launch against a fake server; and `tools/deploy_android.py` (the latest successful artifact selection and the git, gh and upload commands it drives, with fake runners). `python3 -m unittest discover -s tests/tools` must end with `OK`. |
| `fixtures/ldtk/` | A small LDtk project written for the tests with the field names of the LDtk 1.5 JSON (not saved by the LDtk editor): `world.ldtk` (a start room, a hall two cells wide, a room with a hole in the floor, an item room, a 2x2 boss room; tile, auto-layer and entity layers) and `external.ldtk` with its level in `external/Vault.ldtkl`. Used by `tools/test_ldtk_convert.py` and `engine/level_test.lua`. |
| `fixtures/seed_spec/` | Spec modules for the seed validator's tests (`level_spec.lua`, and `strict_spec.lua` with a rule some seeds fail). |
| `pc/level_editor_test.lua` | `tools/level_editor`: the model (tiles, rectangles, flood fill, doors, the item, entities, fields, resize, checks, undo, the file round trip, the LDtk fixture opened and saved back) and the window on the fake love (`pc/level_editor_window.lua`). It covers painting, tools by key, undo, doors and their abilities, entities, rooms from the panel, saving, the play test, and quitting with unsaved changes. `luajit -joff tests/pc/level_editor_test.lua` must end with `OK:`. |
| `pc/boot_pc.lua` | Runs the console boot (`runtime/lua/boot.lua`) on PC against a game, with a fake `l360` table and the graphics stub. `luajit -joff tests/pc/boot_pc.lua` must end with `OK:`. Needs `python3` (it runs the shader build with `--hlsl-only` for the fixture's metadata). |
| `pc/check_libs_test.lua` | `tools/check_libs.lua` passes on the repository, and reports every kind of problem in a copy with a broken library. `luajit tests/pc/check_libs_test.lua` must end with `OK:`. |
| `pc/compat_check_test.lua` | Checks `tools/compat_check.lua` against a fake `love` table (wrapping, pass-through, once-only lines, argument checks, callbacks, `report()`), and that `docs/API_SUBSET.md` and `tools/api_subset_data.lua` are up to date. `luajit -joff tests/pc/compat_check_test.lua` must end with `OK:`. |
| `pc/particles_test.c` | Checks `runtime/l360_particles.c` (the ParticleSystem simulation, which needs no xsdk) built for PC: the pool's cap, lifetimes, emission rate, movement, sizes and colours, emission areas, the three insert modes. `gcc -std=gnu17 -Wall -Wextra -Werror -Iruntime tests/pc/particles_test.c runtime/l360_particles.c -lm -o /tmp/particles_test && /tmp/particles_test` must end with `OK:`. |
| `engine/run.lua` | The engine layer's tests (`engine/`, `lib/anim8`, `lib/bump`) on plain LuaJIT with a small fake `love` (`engine/fake_love.lua`): state stack, fixed timestep, input edges and deadzones, camera, pixel scaling, layer order, anim8, entities, modifiers, seeded random numbers (`engine/rng.lua`: known answers, uniform ranges, independent streams, save state), saves (`engine/save.lua` with a fake `love.filesystem`: round trips, corrupt files, migrations, unlocks, a parser that rejects code), levels (`engine/level.lua`: the LDtk fixture converted with `python3 tools/ldtk_convert.py`, loaded, generated into a procgen map, checked with `procgen.reach`, built into SpriteBatches; needs `python3`), the debug mode (`engine/debug.lua`: off by default, seed entry by directions, modifier list, hitbox overlay), special room types and runs of floors (`procgen.roomtypes`, `procgen.floors`: counts by floor, chance, special rooms as dead ends at their distance, never filler, the boss far away, ten floors that grow, the same floor for the same seed), the seed validator and the level hash check (`procgen.seeds`, `tools/seed_validator.lua`, `tests/console/level_hash_check.lua`), attacks as data (`combat.attacks`: config checks, melee sweeps, shots, bombs and blasts, determinism, no allocation once warm), the platformer module (`engine/modules/platformer` on `lib/bump`: tiles merged into rectangles, solid and one-way collisions, coyote time, jump buffer, jump cut, drop-through, parameters changed by modifiers, the reach numbers), the pixel grid (`engine/pixelgrid.lua`), the soft body (`engine/modules/softbody`: falling, resting without rolling, walls, one-way tiles, pushes, jumps, `inflate`, `set_rest_shape`, the outline in a pixel grid, determinism, nothing allocated per step), the wallet (`engine/modules/wallet`: names, add/can/spend, no negative amounts, state/set_state), room navigation (`engine/modules/rooms`: every door of a generated map walked both ways, arrival points, locks, the minimap's explored cells, the save state, fade and slide transitions), the built-in font (`engine/text.lua`: glyphs, runs, scale, no allocation, and its Font-like adapter for `engine.ui`: measure, wrap, aligned `printf` without allocation), live tuning (`engine/tune.lua`: steps, limits, rounding, held repeat, save and load through a fake filesystem, the overlay), the frame loop, auto-pause (`engine.autopause`: the pad in use leaving, the focus, `autopause = false`, no double push), `examples/engine_demo`, and a static check of what `engine/` and anim8 call against the console's subset. `luajit -joff tests/engine/run.lua` must end with `OK:`, and so must `luajit tests/engine/run.lua` (JIT on for the random number tests only). `luajit -joff tests/pc/boot_pc.lua examples/engine_demo` runs the demo on the console's boot. |
| `fixtures/minimal_game/` | The smallest game: `game.lua`, `conf.lua`, `main.lua` and one shader (`shaders/tint.glsl`), plus a SpriteBatch tile map (`tiles.png`), text, lines and circles, and a ParticleSystem drawn with additive blending. Also runs on LÖVE 11.x. |
| `shaders/` | Shader build tests: the GLSL to HLSL translator, its xost rules and the metadata (with a small HLSL interpreter), and the notices file of `tools/shaders/xost_windows`. `python3 -m unittest discover -s tests/shaders` must end with `OK`; needs no Windows or xost. |
